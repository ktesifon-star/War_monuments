# Пока стоит памятник — живёт память

Карта и каталог памятников Великой Отечественной войны. Проект начинается с Казахстана.

**Сайт:** https://ktesifon-star.github.io/War_monuments/

## Устройство

- `index.html` — разметка и тексты страницы.
- `style.css` — оформление, адаптация и прокрутка каталога.
- `script.js` — карта, поиск, загрузка каталога и карточки.
- `core.js` — проверка данных, поиск и переиспользование маркеров.
- `config.js` — подложка, масштаб, размер страницы каталога. Рамка Казахстана задана единожды в `core.js` и используется картой и проверкой координат.
- `data/monuments.json` — записи памятников. Добавлять материалы нужно сюда.
- `images/` — собственные или разрешённые к публикации фотографии; создайте папку при добавлении первого снимка.
- `tests/` — автоматические проверки.
- `scripts/` — проверка файлов и сборка для публикации.

Нет зависимостей npm и обязательного фреймворка. Карта использует Leaflet 1.9.4 с unpkg и подложку OpenStreetMap. При недоступности Leaflet описания можно открыть в каталоге. Если JSON не загрузился, есть повторная загрузка.

## Локальный запуск

Нужен HTTP-сервер: открытие через `file://` не подходит для модулей и загрузки JSON.

```sh
python -m http.server 8000
```

Откройте http://localhost:8000/ из папки репозитория.

Для проверок нужен Node.js 22 или новее; `npm install` не требуется:

```sh
npm run check
npm run build
```

Сборка создаёт `dist/` с именами ресурсов, содержащими хеш содержимого. Изменение файла автоматически меняет его URL. Не коммитьте `dist/`: его собирает GitHub Actions.

## Добавление памятника

Добавьте объект в массив `data/monuments.json` (между объектами нужна запятая). Пример структуры — не готовая историческая запись:

```json
{
  "id": "settlement-monument-name",
  "name": "Название памятника",
  "region": "Название области или города",
  "location": "Населённый пункт, адрес",
  "coords": [43.259, 76.957],
  "photo": null,
  "photoAuthor": null,
  "photoSource": null,
  "photoPermission": null,
  "sources": [],
  "description": "Проверенное описание памятника"
}
```

- `id` — уникальные латинские строчные буквы, цифры и дефисы; после публикации не менять без необходимости: он используется в ссылках.
- `coords` — сначала **широта**, затем **долгота**. Пример координат выше нельзя копировать для другого памятника. Координаты должны находиться в рамке Казахстана; рамка не проверяет точную государственную границу.
- `region` — единообразное название: именно оно появляется в фильтре.
- `photo` — `null`, если снимка нет. Не добавляйте несуществующий путь или случайную картинку.
- Для фото: сохраните JPG/PNG/WebP в `images/` и задайте путь, например `images/almaty/memorial.webp`. Имена файлов — латинские буквы, цифры, дефисы или подчёркивания. Укажите автора, источник и основание публикации в `photoAuthor`, `photoSource`, `photoPermission`.
- Рекомендуется уменьшить фото до 1600–2000 пикселей по длинной стороне и сжать его. Загружается только фото открытой карточки.
- `sources` — HTTPS-ссылки на источники исторических сведений. Пустой список означает, что ссылки ещё не внесены; не выдумывайте их.
- Не публикуйте личные контакты участников или документы с разрешениями в JSON. Поле `photoPermission` содержит краткое описание основания, сами подтверждения храните отдельно.

После редактирования выполните `npm run check`. Проверяются обязательные поля, дубликаты ID, координаты, пути и наличие фотографий, ссылки и код. В браузере ошибочная запись пропускается, остальные продолжают работать. В CI ошибка данных останавливает проверку.

## Поиск и большой каталог

Поиск учитывает все введённые слова, регистр и замену ё/е. Ввод обрабатывается после паузы 180 мс. Маркеры создаются один раз и переиспользуются; карточки выдаются порциями по 30. Список прокручивается отдельно от карты. Звёзды имеют постоянный размер 18 px.

На обзорном масштабе близкие памятники могут накладываться. Группировка маркеров пока не включена; при тысячах записей следует проверить работу на обычном телефоне и решить, нужна ли группировка. Автоматический тест на 1000 объектов проверяет переиспользование маркеров, а не скорость конкретного устройства.

## Публикация и проверки

`Validate and publish site` запускается на push и pull request, выполняет тесты и сохраняет проверенную сборку `verified-site`. При выбранном источнике GitHub Actions публикация зависит от успешного завершения проверок.

**Одноразовая настройка владельца:** Settings → Pages → Build and deployment → Source → **GitHub Actions**. После переключения запустите Actions → Validate and publish site → Run workflow либо сделайте новый коммит.

До этого переключения прежний режим «Deploy from a branch» продолжает публиковать корень `main` независимо от результата наших тестов. Проверки сами по себе не блокируют старую публикацию. Workflow определяет режим Pages и пропускает свой deploy, если ещё выбран старый режим.

Для изменений предпочтителен pull request: проверьте зелёный результат `Validate and publish site`, затем объедините изменения. Ограничения на слияние ветки задаются отдельно владельцем репозитория.

## Подложка и зависимости

Подложка настраивается в `config.js`: URL, атрибуция и максимальный масштаб должны соответствовать выбранному поставщику. OpenStreetMap используется с видимой атрибуцией и стандартным браузерным кешированием, без скачивания карт для офлайн-работы. Доступность внешних сервисов не гарантируется. Правила: https://operations.osmfoundation.org/policies/tiles/
